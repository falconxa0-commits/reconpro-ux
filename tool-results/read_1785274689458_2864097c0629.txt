   147→   647→### ⚠️ Cover Content Overflow Prevention (Mandatory)
   148→   648→
   149→   649→1. Cover section page margin is 0; total content height ≤ 15638 twips (1200 twips safety margin for cross-engine compatibility — MS Office renders large fonts taller than calculated).
   150→   650→2. Color block Table `height` must use `rule: "exact"` (never `"atLeast"`).
   151→   651→3. Each recipe code includes height budget annotations — verify during generation.
   152→   652→4. **`verticalAlign` must always be `"top"`**. Never use `"center"` or `"bottom"` in exact-height rows — content will be clipped or overflow. Use `spacing.before` on the first paragraph for vertical positioning.
   153→   653→5. **Title font size MUST be dynamically calculated via `calcTitleLayout()`** (see below). Never hardcode font sizes above 40pt for cover titles. Every recipe MUST call `calcTitleLayout()` before building title paragraphs.
   154→   654→6. **Never use `margins.top`/`margins.bottom` for vertical positioning inside exact-height cells**: Cell margins reduce available height unpredictably across MS Office and WPS. Use `spacing.before` on the first paragraph instead. Only `margins.left`/`margins.right` are safe.
   155→   655→7. **Dynamic spacing is mandatory**: Use `calcCoverSpacing()` to compute `spacing.before` values dynamically based on content element count and title line count. Never use fixed large spacing values (e.g., `before: 4500`) that assume a specific title length.
   156→   656→8. **Cover must be a single-page section**: The cover section must produce exactly ONE page. If content overflows to a second page, it means the height budget is violated. Common overflow causes and fixes:
   157→   657→   - Title font too large → use `calcTitleLayout()` to auto-reduce
   158→   658→   - Too many meta lines → reduce font size or remove less important lines
   159→   659→   - Fixed `spacing.before` values too large → use `calcCoverSpacing()` for dynamic values
   160→   660→   - Subtitle + English label + meta lines combined exceed budget → calculate total and reduce spacing
   161→   661→9. **Cover wrapper table MUST use explicit `allNoBorders`**: The outer 16838 wrapper table and ALL nested tables inside the cover MUST set borders to NONE explicitly. Never rely on docx-js default borders (`single/auto/sz=4`). Default borders add ~8 twips per edge, which causes MS Office to calculate a total height slightly exceeding 16838 → content overflows to a blank page 2. WPS is more lenient but MS Office is strict. **This is the #1 cause of "blank page 2 in MS Office but not in WPS".**
   162→   662→
   163→   663→```js
   164→   664→// ✅ MANDATORY: Define and use allNoBorders for every cover table
   165→   665→const NB = { style: BorderStyle.NONE, size: 0, color: "FFFFFF" };
   166→   666→const noBorders = { top: NB, bottom: NB, left: NB, right: NB };
   167→   667→const allNoBorders = { top: NB, bottom: NB, left: NB, right: NB,
   168→   668→                       insideHorizontal: NB, insideVertical: NB };
   169→   669→
   170→   670→new Table({
   171→   671→  borders: allNoBorders,  // ← MANDATORY on every cover table
   172→   672→  // ...
   173→   673→});
   174→   674→```
   175→   675→
   176→   676→10. **Decorative lines MUST use paragraph borders, NEVER text characters**: Horizontal decorative lines (accent strips, dividers, frame edges) must be implemented with `paragraph border.top` or `border.bottom` — never with text characters like `───`, `━━━`, `═══`, or `——————`. Character-drawn lines render at inconsistent widths across MS Office and WPS (font metrics differ), causing lines to appear truncated or misaligned. Paragraph borders render pixel-perfect in both engines and their width is controlled precisely via `indent.left` / `indent.right`.
   177→   677→
   178→   678→```js
   179→   679→// ✅ Correct — paragraph border (R2 style thick accent rule)
   180→   680→new Paragraph({
   181→   681→  indent: { left: 1000, right: 1000 },
   182→   682→  border: { top: { style: BorderStyle.SINGLE, size: 18, color: P.accent, space: 20 } },
   183→   683→  children: [],
   184→   684→})
   185→   685→
   186→   686→// ❌ FORBIDDEN — text character line (renders inconsistently)
   187→   687→new Paragraph({
   188→   688→  children: [new TextRun({ text: "───────────────", color: P.accent })]
   189→   689→})
   190→   690→```
   191→   691→9. **Post-generation overflow check (mandatory)**: After building cover children, estimate total height:
   192→   692→   ```js
   193→   693→   function estimateCoverHeight(elements) {
   194→   694→     let total = 0;
   195→   695→     for (const el of elements) {
   196→   696→       if (el instanceof Table) {
   197→   697→         // Sum row heights (exact rows) or estimate 400 twips per row
   198→   698→         const rows = el.root?.[0]?.rows || [];
   199→   699→         for (const row of rows) {
   200→   700→           total += row.height?.value || 400;
   201→   701→         }
   202→   702→       } else if (el instanceof Paragraph) {
   203→   703→         const fontSize = el.root?.[0]?.size || 24; // half-pts
   204→   704→         // ★ Use pt * 11.5 (= half-pt * 10 * 1.15) for accurate single-spacing estimate
   205→   705→         const lineHeight = Math.max(fontSize * 11.5, 276); // min 276 (default 12pt)
   206→   706→         const spacingBefore = el.spacing?.before || 0;
   207→   707→         const spacingAfter = el.spacing?.after || 0;
   208→   708→         total += lineHeight + spacingBefore + spacingAfter;
   209→   709→       }
   210→   710→     }
   211→   711→     return total;
   212→   712→   }
   213→   713→   // ★ Target: estimateCoverHeight(coverChildren) < 15638 (16838 - 1200 safety)
   214→   714→   ```

   218→   718→### ⚠️ Cover Title Layout — calcTitleLayout() (Mandatory for ALL Recipes)
   219→   719→
   220→   720→**Every cover recipe MUST use `calcTitleLayout()` to determine title font size and line breaks.** Hardcoding font sizes or passing the full title as a single TextRun is FORBIDDEN.
   221→   721→
   222→   722→**Every paragraph with font size > body text MUST set explicit line spacing** to prevent top clipping:
   223→   723→```js
   224→   724→// ★ MANDATORY: prevent inherited small line spacing from clipping large fonts
   225→   725→spacing: { line: Math.ceil(titlePt * 23), lineRule: "atLeast", after: 100 }
   226→   726→// Example: 36pt → line: 828; 44pt → line: 1012
   227→   727→```
   228→   728→Without this, the paragraph inherits body text line spacing (e.g., 560tw), which is shorter than the font height → top of characters gets clipped.
   229→   729→
   230→   730→```js
   231→   731→/**
   232→   732→ * Calculate safe font size and smart line breaks for cover titles.
   233→   733→ * MUST be called by every recipe before building title paragraphs.
   234→   734→ *
   235→   735→ * @param {string}  title          Full title string
   236→   736→ * @param {number}  maxWidthTwips  Available width for title text (twips, after subtracting margins/padding)
   237→   737→ * @param {number}  preferredPt    Desired max font size in pt (default 40)
   238→   738→ * @param {number}  minPt          Minimum allowed font size in pt (default 24)
   239→   739→ * @returns {{ titlePt: number, titleLines: string[] }}
   240→   740→ */
   241→   741→function calcTitleLayout(title, maxWidthTwips, preferredPt = 40, minPt = 24) {
   242→   742→  // Each CJK character width ≈ pt × 20 twips
   243→   743→  const charWidth = (pt) => pt * 20;
   244→   744→  const charsPerLine = (pt) => Math.floor(maxWidthTwips / charWidth(pt));
   245→   745→
   246→   746→  // Try from preferredPt downward until title fits in ≤ 3 lines
   247→   747→  let titlePt = preferredPt;
   248→   748→  let lines;
   249→   749→  while (titlePt >= minPt) {
   250→   750→    const cpl = charsPerLine(titlePt);
   251→   751→    if (cpl < 2) { titlePt -= 2; continue; }
   252→   752→    lines = splitTitleLines(title, cpl);
   253→   753→    if (lines.length <= 3) break;
   254→   754→    titlePt -= 2;
   255→   755→  }
   256→   756→
   257→   757→  // If still > 3 lines at minPt, force 3 lines
   258→   758→  if (!lines || lines.length > 3) {
   259→   759→    const cpl = charsPerLine(minPt);
   260→   760→    lines = splitTitleLines(title, cpl);
   261→   761→    titlePt = minPt;
   262→   762→  }
   263→   763→
   264→   764→  return { titlePt, titleLines: lines };
   265→   765→}
   266→   766→
   267→   767→/**
   268→   768→ * Smart Chinese title line-breaking — breaks at semantic boundaries, never mid-word.
   269→   769→ *
   270→   770→ * Rules:
   271→   771→ * 1. Prefer breaking after particles, punctuation, connectors, underscores, spaces
   272→   772→ * 2. Never split a compound word (e.g., "管理规范" must not become "管理规" + "范")
   273→   773→ * 3. No single-character orphan on the last line — merge into previous line
   274→   774→ * 4. If no good break point found within 60-130% of charsPerLine, break at charsPerLine
   275→   775→ *
   276→   776→ * @param {string} title        Full title string
   277→   777→ * @param {number} charsPerLine Max characters per line at current font size
   278→   778→ * @returns {string[]}          Array of line strings
   279→   779→ */
   280→   780→function splitTitleLines(title, charsPerLine) {
   281→   781→  if (title.length <= charsPerLine) return [title];
   282→   782→
   283→   783→  // Characters that are safe break points (break AFTER these)
   284→   784→  const breakAfter = new Set([
   285→   785→    ...'，。、；：！？',              // CJK punctuation
   286→   786→    ...'的与和及之在于为',            // CJK particles/prepositions
   287→   787→    ...'-_—–·/',                     // connectors
   288→   788→    ...' \t',                         // whitespace
   289→   789→  ]);
   290→   790→
   291→   791→  const lines = [];
   292→   792→  let remaining = title;
   293→   793→
   294→   794→  while (remaining.length > charsPerLine) {
   295→   795→    let breakAt = -1;
   296→   796→
   297→   797→    // Search backward from charsPerLine to 60% for a break point
   298→   798→    for (let i = charsPerLine; i >= Math.floor(charsPerLine * 0.6); i--) {
   299→   799→      if (i < remaining.length && breakAfter.has(remaining[i - 1])) {
   300→   800→        breakAt = i;
   301→   801→        break;
   302→   802→      }
   303→   803→    }
   304→   804→
   305→   805→    // If not found, search forward up to 130%
   306→   806→    if (breakAt === -1) {
   307→   807→      const limit = Math.min(remaining.length, Math.ceil(charsPerLine * 1.3));
   308→   808→      for (let i = charsPerLine + 1; i < limit; i++) {
   309→   809→        if (breakAfter.has(remaining[i - 1])) {
   310→   810→          breakAt = i;
   311→   811→          break;
   312→   812→        }
   313→   813→      }
   314→   814→    }
   315→   815→
   316→   816→    // Last resort: break at charsPerLine, but avoid splitting compound CJK words
   317→   817→    if (breakAt === -1) {
   318→   818→      breakAt = charsPerLine;
   319→   819→      // If both chars at the break boundary are CJK (likely a compound word),
   320→   820→      // step back 1 char to keep the word together
   321→   821→      const prevChar = remaining[breakAt - 1];
   322→   822→      const nextChar = remaining[breakAt];
   323→   823→      if (prevChar && nextChar &&
   324→   824→          !breakAfter.has(prevChar) && !breakAfter.has(nextChar) &&
   325→   825→          /[\u4e00-\u9fff]/.test(prevChar) && /[\u4e00-\u9fff]/.test(nextChar)) {
   326→   826→        breakAt = breakAt - 1;
   327→   827→      }
   328→   828→    }
   329→   829→
   330→   830→    lines.push(remaining.slice(0, breakAt).trim());
   331→   831→    remaining = remaining.slice(breakAt).trim();
   332→   832→  }
   333→   833→  if (remaining) lines.push(remaining);
   334→   834→
   335→   835→  // Prevent single-character orphan on last line — merge into previous
   336→   836→  if (lines.length > 1 && lines[lines.length - 1].length <= 2) {
   337→   837→    const last = lines.pop();
   338→   838→    lines[lines.length - 1] += last;
   339→   839→  }
   340→   840→
   341→   841→  return lines;
   342→   842→}
   343→   843→
   344→   844→/**
   345→   845→ * Calculate dynamic spacing values for cover elements to fit within page height.
   346→   846→ *
   347→   847→ * @param {object} params
   348→   848→ * @param {number} params.titleLineCount   Number of title lines
   349→   849→ * @param {number} params.titlePt          Title font size in pt
   350→   850→ * @param {boolean} params.hasSubtitle     Whether subtitle exists
   351→   851→ * @param {boolean} params.hasEnglishLabel Whether English label exists
   352→   852→ * @param {number} params.metaLineCount    Number of meta info lines
   353→   853→ * @param {number} params.fixedHeight      Sum of fixed-height elements (color strips, accent bars, footer) in twips
   354→   854→ * @param {number} params.pageHeight       Total page height in twips (default 16838)
   355→   855→ * @returns {{ topSpacing, midSpacing, bottomSpacing }}  Spacing values in twips
   356→   856→ */
   357→   857→function calcCoverSpacing(params) {
   358→   858→  const {
   359→   859→    titleLineCount = 1, titlePt = 36, hasSubtitle = false,
   360→   860→    hasEnglishLabel = false, metaLineCount = 0,
   361→   861→    fixedHeight = 800, pageHeight = 16838,
   362→   862→    marginTop = 0, marginBottom = 0,   // ★ NEW: pass actual section margins
   363→   863→  } = params;
   364→   864→
   365→   865→  // ★ Safety margin: 1200 twips (cross-engine: MS Office renders large fonts
   366→   866→  // taller than calculated; extra 400tw buffer prevents footer clipping)
   367→   867→  const SAFETY = 1200;
   368→   868→  // ★ Subtract page margins from available height (cover section may have margins)
   369→   869→  const usableHeight = pageHeight - marginTop - marginBottom - SAFETY;
   370→   870→
   371→   871→  // ★ Accurate height estimation per element:
   372→   872→  const titleHeight = titleLineCount * (titlePt * 23 + 200);
   373→   873→  const subtitleHeight = hasSubtitle ? (12 * 23 + 600) : 0;
   374→   874→  const englishLabelHeight = hasEnglishLabel ? (9 * 23 + 600) : 0;
   375→   875→  const metaHeight = metaLineCount * (10 * 23 + 100);
   376→   876→
   377→   877→  // ★ Account for implicit paragraph heights:
   378→   878→  const implicitParaHeight = 3 * 300;
   379→   879→
   380→   880→  const contentHeight = titleHeight + subtitleHeight + englishLabelHeight +
   381→   881→                        metaHeight + fixedHeight + implicitParaHeight;
   382→   882→
   383→   883→  const remainingSpace = usableHeight - contentHeight;
   384→   884→  const safeRemaining = Math.max(remainingSpace, 400);
   385→   885→
   386→   886→  // ★ Footer protection: bottomSpacing must be ≥ FOOTER_MIN to prevent
   387→   887→  // footer + accent line from being clipped at the cell bottom edge
   388→   888→  const FOOTER_MIN = 800;
   389→   889→  const rawTop = Math.floor(safeRemaining * 0.45);
   390→   890→  const rawBottom = Math.floor(safeRemaining * 0.45);
   391→   891→  const bottomSpacing = Math.max(rawBottom, FOOTER_MIN);
   392→   892→  const topSpacing = Math.max(rawTop - Math.max(0, FOOTER_MIN - rawBottom), 400);
   393→   893→  const midSpacing = Math.max(safeRemaining - topSpacing - bottomSpacing, 0);
   394→   894→
   395→   895→  return { topSpacing, midSpacing, bottomSpacing };
   396→   896→}
   397→   897→```

   426→   926→### ⚠️ CRITICAL — Cover Section Non-Negotiables (ALL Recipes)
   427→   927→
   428→   928→These 3 properties are MANDATORY for every cover implementation (R1–R7). Omitting ANY of them causes cover layout failure:
   429→   929→
   430→   930→1. **Cover section margin = 0**: The cover MUST be in its own section with `page.margin: { top: 0, bottom: 0, left: 0, right: 0 }`. Non-zero margins shrink the wrapper away from page edges → white gaps around the cover ("cover not filling the page"). This is the #1 cause of broken cover layouts.
   431→   931→
   432→   932→2. **Wrapper row exact height**: The outer wrapper table row MUST set `height: { value: 16838, rule: "exact" }`. Without this, content overflow pushes to page 2, or insufficient content leaves bottom whitespace.
   433→   933→
   434→   934→3. **Wrapper table borders = allNoBorders**: MUST explicitly set `borders: allNoBorders`. Default docx-js borders add ~8 twips per edge. MS Office includes border thickness in exact-height calculation → total exceeds 16838 → blank page 2 (WPS is lenient, MS Office is strict).
   435→   935→
   436→   936→**Cover section template (copy this for every Recipe):**
   437→   937→```js
   438→   938→sections: [
   439→   939→  {
   440→   940→    // ⚠️ Cover section — margin MUST be 0, separate from body
   441→   941→    properties: {
   442→   942→      page: {
   443→   943→        size: { width: 11906, height: 16838 },
   444→   944→        margin: { top: 0, bottom: 0, left: 0, right: 0 },
   445→   945→      },
   446→   946→    },
   447→   947→    children: buildCoverRX(config), // ← replace with actual recipe function
   448→   948→  },
   449→   949→  {
   450→   950→    // Body section — normal margins
   451→   951→    properties: {
   452→   952→      type: SectionType.NEXT_PAGE,
   453→   953→      page: {
   454→   954→        size: { width: 11906, height: 16838 },
   455→   955→        margin: { top: 1440, bottom: 1440, left: 1701, right: 1417 },
   456→   956→      },
   457→   957→    },
   458→   958→    children: [...bodyContent],
   459→   959→  },
   460→   960→]
   461→   961→```

   945→  1445→### Recipe R5: Clean White (Academic)
   946→  1446→
   947→  1447→**Visual:** Pure white background + school name + centered title + 2-column meta info table with underlines + footer
   948→  1448→**Use case:** academic thesis, standards documents
   949→  1449→**Architecture:** 16838 outer wrapper (white fill, invisible) + cell margins for page margin simulation. No top/bottom decorative lines.
   950→  1450→
   951→  1451→**Meta info table rules (cross-engine safe):**
   952→  1452→- 2-column table: label + value, **percentage widths only** (`WidthType.PERCENTAGE`)
   953→  1453→- **Table width is adaptive:** 55–75% of page, calculated by `calcR5MetaLayout()`. Table centered via `alignment: CENTER`.
   954→  1454→- **Label column:** adaptive 25–45% of table, **LEFT aligned**, plain text with "：" appended. NO full-width space padding, NO right-alignment.
   955→  1455→- **Label column borders:** none (no bottom border on label cells).
   956→  1456→- **Value column:** remaining %, **LEFT aligned**, `bottom: single sz=4` border = fixed-length underline (consistent length for all rows regardless of text).
   957→  1457→- No left/right/top borders on either column.
   958→  1458→- ⚠️ Do NOT use DXA widths, full-width space padding (`\u3000`), spacer columns, or tab stops — WPS renders them inconsistently.
   959→  1459→- ⚠️ Do NOT use `margins.top` on the wrapper cell — use `spacing.before` on first paragraph instead.
   960→  1460→
   961→  1461→**Known limitation:** When meta lines ≥ 6 AND title has 3 lines, MS Office may render content slightly taller than WPS, potentially clipping the footer line. Mitigate by reducing `midSpacing` or using a smaller title font.
   962→  1462→

   964→  1464→// ── Width-aware title layout (handles mixed Chinese + English) ──
   965→  1465→function estimateTextWidth(text, pt) {
   966→  1466→  let width = 0;
   967→  1467→  for (const ch of text) {
   968→  1468→    const code = ch.codePointAt(0);
   969→  1469→    const isCJK = (code >= 0x4E00 && code <= 0x9FFF) || (code >= 0x3400 && code <= 0x4DBF) ||
   970→  1470→      (code >= 0x3000 && code <= 0x303F) || (code >= 0xFF00 && code <= 0xFFEF) ||
   971→  1471→      (code >= 0x2E80 && code <= 0x2EFF);
   972→  1472→    width += isCJK ? pt * 20 : pt * 11; // CJK: full-width, Latin: ~55% width
   973→  1473→  }
   974→  1474→  return width;
   975→  1475→}
   976→  1476→// Use estimateTextWidth() in calcTitleLayout() instead of simple char count
   977→  1477→// to prevent mid-word breaks in mixed Chinese+English titles like "基于Transformer架构的..."
   978→  1478→
   979→  1479→// ── Meta info table ──
   980→  1480→
   981→  1481→// Calculate adaptive table and label column percentage based on longest label.
   982→  1482→// Returns { tablePct, labelPct } — both as percentages.
   983→  1483→// Uses ONLY WidthType.PERCENTAGE for cross-engine compatibility (MS Office + WPS).
   984→  1484→function calcR5MetaLayout(metaEntries, fontPt = 12) {
   985→  1485→  const maxLabelLen = Math.max(...metaEntries.map(e => [...e.label].length));
   986→  1486→  // Label needs: maxLabelLen chars + "：" + 1 char padding
   987→  1487→  const labelNeedTw = (maxLabelLen + 2) * fontPt * 20;
   988→  1488→  // Value column: fixed ~5000tw for consistent underline length
   989→  1489→  const valueNeedTw = 5000;
   990→  1490→  const totalNeedTw = labelNeedTw + valueNeedTw;
   991→  1491→  // Table width as % of page (11906tw), clamped to 55–75%
   992→  1492→  const tablePct = Math.min(75, Math.max(55, Math.ceil(totalNeedTw / 11906 * 100)));
   993→  1493→  // Label % within the table, clamped to 25–45%
   994→  1494→  const rawLabelPct = Math.ceil(labelNeedTw / (tablePct / 100 * 11906) * 100);
   995→  1495→  return { tablePct, labelPct: Math.max(25, Math.min(45, rawLabelPct)) };
   996→  1496→}

  1157→  1657→### blendColors Utility Function
  1158→  1658→
  1159→  1659→```js
  1160→  1660→function blendColors(hex1, hex2, ratio) {
  1161→  1661→  const p = (s, i) => parseInt(s.replace("#","").slice(i, i+2), 16);
  1162→  1662→  const mix = (c1, c2) => Math.round(c1 + (c2 - c1) * ratio);
  1163→  1663→  const r = mix(p(hex1,0), p(hex2,0)), g = mix(p(hex1,2), p(hex2,2)), b = mix(p(hex1,4), p(hex2,4));
  1164→  1664→  return [r, g, b].map(v => v.toString(16).padStart(2,"0")).join("");
  1165→  1665→}
  1166→  1666→```

  1198→  1698→## Chart Quality Rules
  1199→  1699→
  1200→  1700→### Chart Color Palette
  1201→  1701→
  1202→  1702→Default: **low-saturation (Morandi style)** palette to avoid flashy high-saturation. High-saturation palette only for explicitly energetic scenarios (events/education/creative).
  1203→  1703→
  1204→  1704→```js
  1205→  1705→const chartColors = {
  1206→  1706→  // Default: low saturation, professional (S: 25-40%, L: 55-68%)
  1207→  1707→  default: ["6B9DAD", "C49B72", "7BA68A", "B87472", "9687A8", "C8B87C", "7AADA0", "7A9BB8"],
  1208→  1708→  // Vivid: only for energetic/creative scenes
  1209→  1709→  vivid:   ["2F97B8", "E67E22", "27AE60", "E74C3C", "9B59B6", "F1C40F", "1ABC9C", "3498DB"],
  1210→  1710→};
  1211→  1711→
  1212→  1712→// Scene selection:
  1213→  1713→// - report/whitepaper/consulting/academic/contract → default
  1214→  1714→// - activity/education/creative copy → vivid (optional)
  1215→  1715→```
  1216→  1716→
  1217→  1717→**Color usage rules:**
  1218→  1718→- Max **5 colors** per chart; excess categories use depth variants of same hue
  1219→  1719→- Emphasis data uses document accent color; non-emphasis uses grey `#B0B0B0`
  1220→  1720→- Adjacent segments in pie/bar charts must have hue gap ≥ 60°
  1221→  1721→
  1222→  1722→1. **Anti-overlap**: If >6 x-axis labels, rotate 45° (`plt.xticks(rotation=45, ha='right')`)
  1223→  1723→2. **Anti-stretch**: Always set figure size explicitly (`fig, ax = plt.subplots(figsize=(10, 6))`)
  1224→  1724→3. **Aspect ratio (CRITICAL)**: When embedding in docx, MUST read actual image dimensions and calculate height proportionally. NEVER hardcode both width and height — pie charts become ellipses, radar charts become diamonds.
  1225→  1725→   ```js
  1226→  1726→   const sizeOf = require("image-size");
  1227→  1727→   const dims = sizeOf(chartBuffer);
  1228→  1728→   const displayWidth = 500;
  1229→  1729→   const displayHeight = Math.round(displayWidth * (dims.height / dims.width));
  1230→  1730→   // transformation: { width: displayWidth, height: displayHeight }
  1231→  1731→   ```
  1232→  1732→4. **DPI**: Save at 200+ DPI (`plt.savefig("chart.png", dpi=200, bbox_inches="tight")`)
  1233→  1733→5. **Colors**: Use palette accent color for primary data series
  1234→  1734→6. **Legend**: Place outside plot area if >4 series
  1235→  1735→7. **Square charts**: Pie and radar charts MUST use `figsize=(8, 8)` (equal width/height) to preserve circular/radial shape
  1236→  1736→7. **Grid**: Light gray grid (`ax.grid(True, alpha=0.3)`)

  1241→  1741→
  1242→  1742→### CJK Body Text
  1243→  1743→- **Alignment**: Justified (`AlignmentType.JUSTIFIED`)

  1245→  1745→- **Line spacing**: 1.3x = `spacing: { line: 312 }`
  1246→  1746→- **No heading indent**: Headings must NOT have first-line indent

  1248→  1748→### English Body Text
  1249→  1749→- **Alignment**: Left (`AlignmentType.LEFT`)
  1250→  1750→- **No indent**
  1251→  1751→- **Line spacing**: Same 1.3x
  1252→  1752→
  1253→  1753→### Table Numbers
  1254→  1754→- Right-aligned in cells
  1255→  1755→- Use monospace or tabular figures if available
  1256→  1756→
  1257→  1757→### Headings
  1258→  1758→- No first-line indent
  1259→  1759→- `spacing: { before: 240, after: 120 }` (H1: before 360)
  1260→  1760→- Bold, palette.primary color

  1262→  1762→### 1.3x Line Spacing — MANDATORY
  1263→  1763→Every document, every paragraph. `spacing: { line: 312 }`. No exceptions unless scene explicitly overrides (e.g., resume uses 1.15x).
