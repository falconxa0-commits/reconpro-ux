     1→     1  # Design System — DOCX Skill
     2→     2  
     3→     3  ## Color Philosophy
     4→     4  
     5→     5  GLM uses a **mood-driven dynamic color system** instead of fixed named palettes. Colors are constructed from three dimensions:
     6→     6  
     7→     7  ### Three Dimensions of Document Color
     8→     8  
     9→     9  | Dimension | Description | Range |
    10→    10  |-----------|-------------|-------|
    11→    11  | **Temperature** | Warm ↔ Cool | Warm (consulting, education) ↔ Cool (tech, medical) |
    12→    12  | **Weight** | Light ↔ Heavy | Light (resume, proposal) ↔ Heavy (legal, academic) |
    13→    13  | **Energy** | Calm ↔ Active | Calm (official, contract) ↔ Active (report, presentation) |
    14→    14  
    15→    15  ### Color Token System
    16→    16  
    17→    17  Every document uses 5 color tokens. These are **computed** based on the document's mood, not selected from a fixed list.
    18→    18  
    19→    19  | Token | Role | Guidance |
    20→    20  |-------|------|----------|
    21→    21  | `primary` | Headings, cover title | Dark, authoritative. Derived from Temperature + Weight. |
    22→    22  | `body` | Body text | Near-black with subtle warmth/coolness. Always high contrast. |
    23→    23  | `secondary` | Captions, footnotes | Mid-tone gray. Legible but visually recessive. |
    24→    24  | `accent` | Table headers, lines, links | The "personality" color. Reflects document Energy. |
    25→    25  | `surface` | Table alternating rows, card backgrounds | Very light tint of accent or neutral. |
    26→    26

   157→   157  ### Visual Profile Color Guidance
   158→   158  
   159→   159  For **Profile B (Visual)** scenes — resume, copywriting, and other non-formal documents — prefer **warm neutral** tones aligned with the "Invisible Precision" design philosophy:
   160→   160  
   161→   161  - **Body text**: Use warm dark neutrals (`#37352F`, `#303030`, `#3A3430`) instead of cool blue-grays. This reduces eye strain.
   162→   162  - **Surface/background**: Use warm near-white (`#F7F7F7`, `#FAFAF8`, `#FBF9F7`) instead of cool tints.
   163→   163  - **Accent colors**: Use sparingly and only for functional differentiation (section headers, key metrics, links). 95% of the document should remain monochromatic (black, white, gray).
   164→   164  - **Tables**: Prefer the **Zebra Stripe** style (see Table Styles §2) — hierarchy through background contrast with minimal borders. Fallback: Horizontal-Only.
   165→   165  
   166→   166  This does NOT apply to Profile A (Formal) scenes (report, academic, contract, official-doc, exam), which must retain pure black `"000000"` body text per regulatory standards.
   167→   167  
   168→   168  ### Custom Color Generation
   169→   169  
   170→   170  When the pre-defined recipes don't fit, construct colors using these rules:
   171→   171  
   172→   172  1. **primary**: Start from `hsl(hue, 25-40%, 10-18%)` — dark, desaturated
   173→   173  2. **body**: primary lightened 5-8% — readable dark
   174→   174  3. **secondary**: primary lightened 30-40% — clearly subordinate
   175→   175  4. **accent**: Choose a hue reflecting the domain, `hsl(domainHue, 30-50%, 45-55%)`
   176→   176  5. **surface**: accent desaturated to 5-10%, lightened to 96-98%
   177→   177  
   178→   178  **Contrast check**: body text on white must achieve WCAG AA (≥4.5:1). All recipes above pass this.

   255→   255  ## Table Styles
   256→   256  
   257→   257  **Profile routing:** Profile A (Formal: report, academic, contract, exam) → Three-Line Table or Horizontal-Only Table. Profile B (Visual: resume, copywriting) → Zebra Stripe (preferred) or Horizontal-Only Table.
   258→   258  
   259→   259  ### 1. Three-Line Table (三线表) — Academic
   260→   260  
   261→   261  Only three horizontal lines: top of table, bottom of header, bottom of table.
   262→   262  
   263→   263  ```js
   264→   264  const threeLineTable = new Table({
   265→   265    width: { size: 100, type: WidthType.PERCENTAGE },
   266→   266    borders: {
   267→   267      top: { style: BorderStyle.SINGLE, size: 4, color: "000000" },
   268→   268      bottom: { style: BorderStyle.SINGLE, size: 4, color: "000000" },
   269→   269      left: { style: BorderStyle.NONE },
   270→   270      right: { style: BorderStyle.NONE },
   271→   271      insideHorizontal: { style: BorderStyle.NONE },
   272→   272      insideVertical: { style: BorderStyle.NONE },
   273→   273    },
   274→   274    rows: [
   275→   275      new TableRow({
   276→   276        children: headerCells.map(text => new TableCell({
   277→   277          children: [new Paragraph({ children: [new TextRun({ text, bold: true, size: 21 })] })],
   278→   278          borders: {
   279→   279            bottom: { style: BorderStyle.SINGLE, size: 2, color: "000000" },
   280→   280            top: { style: BorderStyle.NONE },
   281→   281            left: { style: BorderStyle.NONE },
   282→   282            right: { style: BorderStyle.NONE },
   283→   283          },
   284→   284          margins: { top: 60, bottom: 60, left: 120, right: 120 },
   285→   285        })),
   286→   286      }),
   287→   287      // ... data rows with all borders NONE
   288→   288    ],
   289→   289  });
   290→   290  ```
   291→   291  
   292→   292  ### 2. Zebra Stripe — Data Reports
   293→   293  
   294→   294  ```js
   295→   295  function zebraRow(cells, index, palette) {
   296→   296    return new TableRow({
   297→   297      children: cells.map(text => new TableCell({
   298→   298        children: [new Paragraph({ children: [new TextRun({ text, size: 21 })] })],
   299→   299        shading: index % 2 === 0
   300→   300          ? { type: ShadingType.CLEAR, fill: palette.surface }
   301→   301          : { type: ShadingType.CLEAR, fill: "FFFFFF" },
   302→   302        margins: { top: 60, bottom: 60, left: 120, right: 120 },
   303→   303      })),
   304→   304    });
   305→   305  }
   306→   306  ```
   307→   307  
   308→   308  ### 3. Horizontal-Only — Business (Default)
   309→   309  
   310→   310  ```js
   311→   311  const horizontalTable = new Table({
   312→   312    width: { size: 100, type: WidthType.PERCENTAGE },
   313→   313    borders: {
   314→   314      top: { style: BorderStyle.SINGLE, size: 2, color: palette.accent.replace("#","") },
   315→   315      bottom: { style: BorderStyle.SINGLE, size: 2, color: palette.accent.replace("#","") },
   316→   316      left: { style: BorderStyle.NONE },
   317→   317      right: { style: BorderStyle.NONE },
   318→   318      insideHorizontal: { style: BorderStyle.SINGLE, size: 1, color: "D0D0D0" },
   319→   319      insideVertical: { style: BorderStyle.NONE },
   320→   320    },
   321→   321    rows: [/* header row with accent shading, then data rows */],
   322→   322  });
   323→   323  ```
   324→   324  
   325→   325  **⚠️ CRITICAL**: Always set `margins` at the Table or TableCell level. Without margins, text touches cell borders.
   326→   326  
   327→   327  ### Table Color Token Derivation
   328→   328  
   329→   329  Each palette in `coverPalettes` provides a `table` object with pre-computed colors for all 3 table styles:
   330→   330  
   331→   331  | Token | Used in | Description |
   332→   332  |-------|---------|-------------|
   333→   333  | `table.headerBg` | Zebra Stripe, Horizontal-Only | Table header background color |
   334→   334  | `table.headerText` | Zebra Stripe, Horizontal-Only | Table header text color (must pass WCAG AA contrast) |
   335→   335  | `table.accentLine` | Three-Line | Top/bottom/header-bottom line color |
   336→   336  | `table.innerLine` | Horizontal-Only | Inner horizontal separator line color |
   337→   337  | `table.surface` | Zebra Stripe | Alternating row background (light tint) |
   338→   338  
   339→   339  **Usage:**
   340→   340  ```js
   341→   341  const palette = coverPalettes["DS-1"];
   342→   342  const t = palette.table;
   343→   343  // Three-Line: use t.accentLine for border colors
   344→   344  // Zebra: use t.headerBg, t.headerText, t.surface
   345→   345  // Horizontal: use t.headerBg, t.headerText, t.innerLine
   346→   346  ```
   347→   347  
   348→   348  **⚠️ High-saturation accent override**: For DM-1, FG-1, and SN-2, the table colors are intentionally darkened/desaturated relative to the cover accent. Bright accent colors that look good on dark cover backgrounds are too eye-straining on white body pages. Always use `palette.table.*` for tables, never the raw `palette.accent`.

   353→   353  ## Cover Page Design System
   354→   354  
   355→   355  ### Design Philosophy
   356→   356  
   357→   357  Covers use **7 validated layout recipes** + **parameterized variants** instead of free combination. Each recipe's background, layout, and decoration are visually verified. Differentiation comes from **palette × font size × content variation**.
   358→   358  
   359→   359  **Architecture principle:** All recipes use a **single 16838 outer wrapper table** (one row, exact height). Recipes R1/R2/R3 use **ZERO nested tables** — all decoration is achieved via **paragraph borders** (left/right/top/bottom). This ensures maximum cross-engine stability (MS Office + WPS).
   360→   360  
   361→   361  ### Cover Color Palettes (Dark Mode + Light Mode)
   362→   362  
   363→   363  Each palette defines 3 core colors (Background, Primary, Accent) + derived cover/table tokens.
   364→   364  
   365→   365  ⚠️ **Disambiguation: `cover.titleColor` is a COLOR value, not title text.** All keys under `cover: { ... }` are **color hex codes** for styling cover text elements. They are NOT text content. The actual title text comes from `config.title`. Never use `P.titleColor` as the `text` parameter of a `TextRun` — it must only be used as the `color` parameter.
   366→   366  
   367→   367  ```js
   368→   368  // ✅ Correct — config.title is the text, P.titleColor is the color
   369→   369  new TextRun({ text: config.title, color: P.titleColor })
   370→   370  
   371→   371  // ❌ WRONG — using color value as text content
   372→   372  new TextRun({ text: P.titleColor, color: P.titleColor })  // displays "FFFFFF" as visible text!
   373→   373  ```

   647→   647  ### ⚠️ Cover Content Overflow Prevention (Mandatory)
   648→   648  
   649→   649  1. Cover section page margin is 0; total content height ≤ 15638 twips (1200 twips safety margin for cross-engine compatibility — MS Office renders large fonts taller than calculated).
   650→   650  2. Color block Table `height` must use `rule: "exact"` (never `"atLeast"`).
   651→   651  3. Each recipe code includes height budget annotations — verify during generation.
   652→   652  4. **`verticalAlign` must always be `"top"`**. Never use `"center"` or `"bottom"` in exact-height rows — content will be clipped or overflow. Use `spacing.before` on the first paragraph for vertical positioning.
   653→   653  5. **Title font size MUST be dynamically calculated via `calcTitleLayout()`** (see below). Never hardcode font sizes above 40pt for cover titles. Every recipe MUST call `calcTitleLayout()` before building title paragraphs.
   654→   654  6. **Never use `margins.top`/`margins.bottom` for vertical positioning inside exact-height cells**: Cell margins reduce available height unpredictably across MS Office and WPS. Use `spacing.before` on the first paragraph instead. Only `margins.left`/`margins.right` are safe.
   655→   655  7. **Dynamic spacing is mandatory**: Use `calcCoverSpacing()` to compute `spacing.before` values dynamically based on content element count and title line count. Never use fixed large spacing values (e.g., `before: 4500`) that assume a specific title length.
   656→   656  8. **Cover must be a single-page section**: The cover section must produce exactly ONE page. If content overflows to a second page, it means the height budget is violated. Common overflow causes and fixes:
   657→   657     - Title font too large → use `calcTitleLayout()` to auto-reduce
   658→   658     - Too many meta lines → reduce font size or remove less important lines
   659→   659     - Fixed `spacing.before` values too large → use `calcCoverSpacing()` for dynamic values
   660→   660     - Subtitle + English label + meta lines combined exceed budget → calculate total and reduce spacing
   661→   661  9. **Cover wrapper table MUST use explicit `allNoBorders`**: The outer 16838 wrapper table and ALL nested tables inside the cover MUST set borders to NONE explicitly. Never rely on docx-js default borders (`single/auto/sz=4`). Default borders add ~8 twips per edge, which causes MS Office to calculate a total height slightly exceeding 16838 → content overflows to a blank page 2. WPS is more lenient but MS Office is strict. **This is the #1 cause of "blank page 2 in MS Office but not in WPS".**
   662→   662  
   663→   663  ```js
   664→   664  // ✅ MANDATORY: Define and use allNoBorders for every cover table
   665→   665  const NB = { style: BorderStyle.NONE, size: 0, color: "FFFFFF" };
   666→   666  const noBorders = { top: NB, bottom: NB, left: NB, right: NB };
   667→   667  const allNoBorders = { top: NB, bottom: NB, left: NB, right: NB,
   668→   668                         insideHorizontal: NB, insideVertical: NB };
   669→   669  
   670→   670  new Table({
   671→   671    borders: allNoBorders,  // ← MANDATORY on every cover table
   672→   672    // ...
   673→   673  });
   674→   674  ```
   675→   675  
   676→   676  10. **Decorative lines MUST use paragraph borders, NEVER text characters**: Horizontal decorative lines (accent strips, dividers, frame edges) must be implemented with `paragraph border.top` or `border.bottom` — never with text characters like `───`, `━━━`, `═══`, or `——————`. Character-drawn lines render at inconsistent widths across MS Office and WPS (font metrics differ), causing lines to appear truncated or misaligned. Paragraph borders render pixel-perfect in both engines and their width is controlled precisely via `indent.left` / `indent.right`.
   677→   677  
   678→   678  ```js
   679→   679  // ✅ Correct — paragraph border (R2 style thick accent rule)
   680→   680  new Paragraph({
   681→   681    indent: { left: 1000, right: 1000 },
   682→   682    border: { top: { style: BorderStyle.SINGLE, size: 18, color: P.accent, space: 20 } },
   683→   683    children: [],
   684→   684  })
   685→   685  
   686→   686  // ❌ FORBIDDEN — text character line (renders inconsistently)
   687→   687  new Paragraph({
   688→   688    children: [new TextRun({ text: "───────────────", color: P.accent })]
   689→   689  })
   690→   690  ```
   691→   691  9. **Post-generation overflow check (mandatory)**: After building cover children, estimate total height:
   692→   692     ```js
   693→   693     function estimateCoverHeight(elements) {
   694→   694       let total = 0;
   695→   695       for (const el of elements) {
   696→   696         if (el instanceof Table) {
   697→   697           // Sum row heights (exact rows) or estimate 400 twips per row
   698→   698           const rows = el.root?.[0]?.rows || [];
   699→   699           for (const row of rows) {
   700→   700             total += row.height?.value || 400;
   701→   701           }
   702→   702         } else if (el instanceof Paragraph) {
   703→   703           const fontSize = el.root?.[0]?.size || 24; // half-pts
   704→   704           // ★ Use pt * 11.5 (= half-pt * 10 * 1.15) for accurate single-spacing estimate
   705→   705           const lineHeight = Math.max(fontSize * 11.5, 276); // min 276 (default 12pt)
   706→   706           const spacingBefore = el.spacing?.before || 0;
   707→   707           const spacingAfter = el.spacing?.after || 0;
   708→   708           total += lineHeight + spacingBefore + spacingAfter;
   709→   709         }
   710→   710       }
   711→   711       return total;
   712→   712     }
   713→   713     // ★ Target: estimateCoverHeight(coverChildren) < 15638 (16838 - 1200 safety)
   714→   714     ```

   718→   718  ### ⚠️ Cover Title Layout — calcTitleLayout() (Mandatory for ALL Recipes)
   719→   719  
   720→   720  **Every cover recipe MUST use `calcTitleLayout()` to determine title font size and line breaks.** Hardcoding font sizes or passing the full title as a single TextRun is FORBIDDEN.
   721→   721  
   722→   722  **Every paragraph with font size > body text MUST set explicit line spacing** to prevent top clipping:
   723→   723  ```js
   724→   724  // ★ MANDATORY: prevent inherited small line spacing from clipping large fonts
   725→   725  spacing: { line: Math.ceil(titlePt * 23), lineRule: "atLeast", after: 100 }
   726→   726  // Example: 36pt → line: 828; 44pt → line: 1012
   727→   727  ```
   728→   728  Without this, the paragraph inherits body text line spacing (e.g., 560tw), which is shorter than the font height → top of characters gets clipped.
   729→   729  
   730→   730  ```js
   731→   731  /**
   732→   732   * Calculate safe font size and smart line breaks for cover titles.
   733→   733   * MUST be called by every recipe before building title paragraphs.
   734→   734   *
   735→   735   * @param {string}  title          Full title string
   736→   736   * @param {number}  maxWidthTwips  Available width for title text (twips, after subtracting margins/padding)
   737→   737   * @param {number}  preferredPt    Desired max font size in pt (default 40)
   738→   738   * @param {number}  minPt          Minimum allowed font size in pt (default 24)
   739→   739   * @returns {{ titlePt: number, titleLines: string[] }}
   740→   740   */
   741→   741  function calcTitleLayout(title, maxWidthTwips, preferredPt = 40, minPt = 24) {
   742→   742    // Each CJK character width ≈ pt × 20 twips
   743→   743    const charWidth = (pt) => pt * 20;
   744→   744    const charsPerLine = (pt) => Math.floor(maxWidthTwips / charWidth(pt));
   745→   745  
   746→   746    // Try from preferredPt downward until title fits in ≤ 3 lines
   747→   747    let titlePt = preferredPt;
   748→   748    let lines;
   749→   749    while (titlePt >= minPt) {
   750→   750      const cpl = charsPerLine(titlePt);
   751→   751      if (cpl < 2) { titlePt -= 2; continue; }
   752→   752      lines = splitTitleLines(title, cpl);
   753→   753      if (lines.length <= 3) break;
   754→   754      titlePt -= 2;
   755→   755    }
   756→   756  
   757→   757    // If still > 3 lines at minPt, force 3 lines
   758→   758    if (!lines || lines.length > 3) {
   759→   759      const cpl = charsPerLine(minPt);
   760→   760      lines = splitTitleLines(title, cpl);
   761→   761      titlePt = minPt;
   762→   762    }
   763→   763  
   764→   764    return { titlePt, titleLines: lines };
   765→   765  }
   766→   766  
   767→   767  /**
   768→   768   * Smart Chinese title line-breaking — breaks at semantic boundaries, never mid-word.
   769→   769   *
   770→   770   * Rules:
   771→   771   * 1. Prefer breaking after particles, punctuation, connectors, underscores, spaces
   772→   772   * 2. Never split a compound word (e.g., "管理规范" must not become "管理规" + "范")
   773→   773   * 3. No single-character orphan on the last line — merge into previous line
   774→   774   * 4. If no good break point found within 60-130% of charsPerLine, break at charsPerLine
   775→   775   *
   776→   776   * @param {string} title        Full title string
   777→   777   * @param {number} charsPerLine Max characters per line at current font size
   778→   778   * @returns {string[]}          Array of line strings
   779→   779   */
   780→   780  function splitTitleLines(title, charsPerLine) {
   781→   781    if (title.length <= charsPerLine) return [title];
   782→   782  
   783→   783    // Characters that are safe break points (break AFTER these)
   784→   784    const breakAfter = new Set([
   785→   785      ...'，。、；：！？',              // CJK punctuation
   786→   786      ...'的与和及之在于为',            // CJK particles/prepositions
   787→   787      ...'-_—–·/',                     // connectors
   788→   788      ...' \t',                         // whitespace
   789→   789    ]);
   790→   790  
   791→   791    const lines = [];
   792→   792    let remaining = title;
   793→   793  
   794→   794    while (remaining.length > charsPerLine) {
   795→   795      let breakAt = -1;
   796→   796  
   797→   797      // Search backward from charsPerLine to 60% for a break point
   798→   798      for (let i = charsPerLine; i >= Math.floor(charsPerLine * 0.6); i--) {
   799→   799        if (i < remaining.length && breakAfter.has(remaining[i - 1])) {
   800→   800          breakAt = i;
   801→   801          break;
   802→   802        }
   803→   803      }
   804→   804  
   805→   805      // If not found, search forward up to 130%
   806→   806      if (breakAt === -1) {
   807→   807        const limit = Math.min(remaining.length, Math.ceil(charsPerLine * 1.3));
   808→   808        for (let i = charsPerLine + 1; i < limit; i++) {
   809→   809          if (breakAfter.has(remaining[i - 1])) {
   810→   810            breakAt = i;
   811→   811            break;
   812→   812          }
   813→   813        }
   814→   814      }
   815→   815  
   816→   816      // Last resort: break at charsPerLine, but avoid splitting compound CJK words
   817→   817      if (breakAt === -1) {
   818→   818        breakAt = charsPerLine;
   819→   819        // If both chars at the break boundary are CJK (likely a compound word),
   820→   820        // step back 1 char to keep the word together
   821→   821        const prevChar = remaining[breakAt - 1];
   822→   822        const nextChar = remaining[breakAt];
   823→   823        if (prevChar && nextChar &&
   824→   824            !breakAfter.has(prevChar) && !breakAfter.has(nextChar) &&
   825→   825            /[\u4e00-\u9fff]/.test(prevChar) && /[\u4e00-\u9fff]/.test(nextChar)) {
   826→   826          breakAt = breakAt - 1;
   827→   827        }
   828→   828      }
   829→   829  
   830→   830      lines.push(remaining.slice(0, breakAt).trim());
   831→   831      remaining = remaining.slice(breakAt).trim();
   832→   832    }
   833→   833    if (remaining) lines.push(remaining);
   834→   834  
   835→   835    // Prevent single-character orphan on last line — merge into previous
   836→   836    if (lines.length > 1 && lines[lines.length - 1].length <= 2) {
   837→   837      const last = lines.pop();
   838→   838      lines[lines.length - 1] += last;
   839→   839    }
   840→   840  
   841→   841    return lines;
   842→   842  }
   843→   843  
   844→   844  /**
   845→   845   * Calculate dynamic spacing values for cover elements to fit within page height.
   846→   846   *
   847→   847   * @param {object} params
   848→   848   * @param {number} params.titleLineCount   Number of title lines
   849→   849   * @param {number} params.titlePt          Title font size in pt
   850→   850   * @param {boolean} params.hasSubtitle     Whether subtitle exists
   851→   851   * @param {boolean} params.hasEnglishLabel Whether English label exists
   852→   852   * @param {number} params.metaLineCount    Number of meta info lines
   853→   853   * @param {number} params.fixedHeight      Sum of fixed-height elements (color strips, accent bars, footer) in twips
   854→   854   * @param {number} params.pageHeight       Total page height in twips (default 16838)
   855→   855   * @returns {{ topSpacing, midSpacing, bottomSpacing }}  Spacing values in twips
   856→   856   */
   857→   857  function calcCoverSpacing(params) {
   858→   858    const {
   859→   859      titleLineCount = 1, titlePt = 36, hasSubtitle = false,
   860→   860      hasEnglishLabel = false, metaLineCount = 0,
   861→   861      fixedHeight = 800, pageHeight = 16838,
   862→   862      marginTop = 0, marginBottom = 0,   // ★ NEW: pass actual section margins
   863→   863    } = params;
   864→   864  
   865→   865    // ★ Safety margin: 1200 twips (cross-engine: MS Office renders large fonts
   866→   866    // taller than calculated; extra 400tw buffer prevents footer clipping)
   867→   867    const SAFETY = 1200;
   868→   868    // ★ Subtract page margins from available height (cover section may have margins)
   869→   869    const usableHeight = pageHeight - marginTop - marginBottom - SAFETY;
   870→   870  
   871→   871    // ★ Accurate height estimation per element:
   872→   872    const titleHeight = titleLineCount * (titlePt * 23 + 200);
   873→   873    const subtitleHeight = hasSubtitle ? (12 * 23 + 600) : 0;
   874→   874    const englishLabelHeight = hasEnglishLabel ? (9 * 23 + 600) : 0;
   875→   875    const metaHeight = metaLineCount * (10 * 23 + 100);
   876→   876  
   877→   877    // ★ Account for implicit paragraph heights:
   878→   878    const implicitParaHeight = 3 * 300;
   879→   879  
   880→   880    const contentHeight = titleHeight + subtitleHeight + englishLabelHeight +
   881→   881                          metaHeight + fixedHeight + implicitParaHeight;
   882→   882  
   883→   883    const remainingSpace = usableHeight - contentHeight;
   884→   884    const safeRemaining = Math.max(remainingSpace, 400);
   885→   885  
   886→   886    // ★ Footer protection: bottomSpacing must be ≥ FOOTER_MIN to prevent
   887→   887    // footer + accent line from being clipped at the cell bottom edge
   888→   888    const FOOTER_MIN = 800;
   889→   889    const rawTop = Math.floor(safeRemaining * 0.45);
   890→   890    const rawBottom = Math.floor(safeRemaining * 0.45);
   891→   891    const bottomSpacing = Math.max(rawBottom, FOOTER_MIN);
   892→   892    const topSpacing = Math.max(rawTop - Math.max(0, FOOTER_MIN - rawBottom), 400);
   893→   893    const midSpacing = Math.max(safeRemaining - topSpacing - bottomSpacing, 0);
   894→   894  
   895→   895    return { topSpacing, midSpacing, bottomSpacing };
   896→   896  }
   897→   897  ```

   926→   926  ### ⚠️ CRITICAL — Cover Section Non-Negotiables (ALL Recipes)
   927→   927  
   928→   928  These 3 properties are MANDATORY for every cover implementation (R1–R7). Omitting ANY of them causes cover layout failure:
   929→   929  
   930→   930  1. **Cover section margin = 0**: The cover MUST be in its own section with `page.margin: { top: 0, bottom: 0, left: 0, right: 0 }`. Non-zero margins shrink the wrapper away from page edges → white gaps around the cover ("cover not filling the page"). This is the #1 cause of broken cover layouts.
   931→   931  
   932→   932  2. **Wrapper row exact height**: The outer wrapper table row MUST set `height: { value: 16838, rule: "exact" }`. Without this, content overflow pushes to page 2, or insufficient content leaves bottom whitespace.
   933→   933  
   934→   934  3. **Wrapper table borders = allNoBorders**: MUST explicitly set `borders: allNoBorders`. Default docx-js borders add ~8 twips per edge. MS Office includes border thickness in exact-height calculation → total exceeds 16838 → blank page 2 (WPS is lenient, MS Office is strict).
   935→   935  
   936→   936  **Cover section template (copy this for every Recipe):**
   937→   937  ```js
   938→   938  sections: [

   941→   941      properties: {
   942→   942        page: {
   943→   943          size: { width: 11906, height: 16838 },
   944→   944          margin: { top: 0, bottom: 0, left: 0, right: 0 },
   945→   945        },
   946→   946      },
   947→   947      children: buildCoverRX(config), // ← replace with actual recipe function

   955→   955          margin: { top: 1440, bottom: 1440, left: 1701, right: 1417 },
   956→   956        },
   957→   957      },
   958→   958      children: [...bodyContent],
   959→   959    },

  1445→  1445  ### Recipe R5: Clean White (Academic)
  1446→  1446  
  1447→  1447  **Visual:** Pure white background + school name + centered title + 2-column meta info table with underlines + footer
  1448→  1448  **Use case:** academic thesis, standards documents
  1449→  1449  **Architecture:** 16838 outer wrapper (white fill, invisible) + cell margins for page margin simulation. No top/bottom decorative lines.
  1450→  1450  
  1451→  1451  **Meta info table rules (cross-engine safe):**
  1452→  1452  - 2-column table: label + value, **percentage widths only** (`WidthType.PERCENTAGE`)
  1453→  1453  - **Table width is adaptive:** 55–75% of page, calculated by `calcR5MetaLayout()`. Table centered via `alignment: CENTER`.
  1454→  1454  - **Label column:** adaptive 25–45% of table, **LEFT aligned**, plain text with "：" appended. NO full-width space padding, NO right-alignment.
  1455→  1455  - **Label column borders:** none (no bottom border on label cells).
  1456→  1456  - **Value column:** remaining %, **LEFT aligned**, `bottom: single sz=4` border = fixed-length underline (consistent length for all rows regardless of text).
  1457→  1457  - No left/right/top borders on either column.
  1458→  1458  - ⚠️ Do NOT use DXA widths, full-width space padding (`\u3000`), spacer columns, or tab stops — WPS renders them inconsistently.
  1459→  1459  - ⚠️ Do NOT use `margins.top` on the wrapper cell — use `spacing.before` on first paragraph instead.
  1460→  1460  
  1461→  1461  **Known limitation:** When meta lines ≥ 6 AND title has 3 lines, MS Office may render content slightly taller than WPS, potentially clipping the footer line. Mitigate by reducing `midSpacing` or using a smaller title font.

  1465→  1465  function estimateTextWidth(text, pt) {
  1466→  1466    let width = 0;
  1467→  1467    for (const ch of text) {
  1468→  1468      const code = ch.codePointAt(0);
  1469→  1469      const isCJK = (code >= 0x4E00 && code <= 0x9FFF) || (code >= 0x3400 && code <= 0x4DBF) ||
  1470→  1470        (code >= 0x3000 && code <= 0x303F) || (code >= 0xFF00 && code <= 0xFFEF) ||
  1471→  1471        (code >= 0x2E80 && code <= 0x2EFF);
  1472→  1472      width += isCJK ? pt * 20 : pt * 11; // CJK: full-width, Latin: ~55% width
  1473→  1473    }
  1474→  1474    return width;
  1475→  1475  }

  1477→  1477  // to prevent mid-word breaks in mixed Chinese+English titles like "基于Transformer架构的..."

  1484→  1484  function calcR5MetaLayout(metaEntries, fontPt = 12) {

  1486→  1486    // Label needs: maxLabelLen chars + "：" + 1 char padding

  1488→  1488    // Value column: fixed ~5000tw for consistent underline length
  1489→  1489    const valueNeedTw = 5000;
  1490→  1490    const totalNeedTw = labelNeedTw + valueNeedTw;
  1491→  1491    // Table width as % of page (11906tw), clamped to 55–75%
  1492→  1492    const tablePct = Math.min(75, Math.max(55, Math.ceil(totalNeedTw / 11906 * 100)));
  1493→  1493    // Label % within the table, clamped to 25–45%
  1494→  1494    const rawLabelPct = Math.ceil(labelNeedTw / (tablePct / 100 * 11906) * 100);

  1657→  1657  ### blendColors Utility Function
  1658→  1658  
  1659→  1659  ```js
  1660→  1660  function blendColors(hex1, hex2, ratio) {
  1661→  1661    const p = (s, i) => parseInt(s.replace("#","").slice(i, i+2), 16);
  1662→  1662    const mix = (c1, c2) => Math.round(c1 + (c2 - c1) * ratio);
  1663→  1663    const r = mix(p(hex1,0), p(hex2,0)), g = mix(p(hex1,2), p(hex2,2)), b = mix(p(hex1,4), p(hex2,4));
  1664→  1664    return [r, g, b].map(v => v.toString(16).padStart(2,"0")).join("");
  1665→  1665  }

  1699→  1699  
  1700→  1700  ### Chart Color Palette
  1701→  1701  
  1702→  1702  Default: **low-saturation (Morandi style)** palette to avoid flashy high-saturation. High-saturation palette only for explicitly energetic scenarios (events/education/creative).
  1703→  1703  
  1704→  1704  ```js
  1705→  1705  const chartColors = {
  1706→  1706    // Default: low saturation, professional (S: 25-40%, L: 55-68%)
  1707→  1707    default: ["6B9DAD", "C49B72", "7BA68A", "B87472", "9687A8", "C8B87C", "7AADA0", "7A9BB8"],
  1708→  1708    // Vivid: only for energetic/creative scenes
  1709→  1709    vivid:   ["2F97B8", "E67E22", "27AE60", "E74C3C", "9B59B6", "F1C40F", "1ABC9C", "3498DB"],
  1710→  1710  };
  1711→  1711  
  1712→  1712  // Scene selection:
  1713→  1713  // - report/whitepaper/consulting/academic/contract → default
  1714→  1714  // - activity/education/creative copy → vivid (optional)
  1715→  1715  ```
  1716→  1716  
  1717→  1717  **Color usage rules:**
  1718→  1718  - Max **5 colors** per chart; excess categories use depth variants of same hue
  1719→  1719  - Emphasis data uses document accent color; non-emphasis uses grey `#B0B0B0`
  1720→  1720  - Adjacent segments in pie/bar charts must have hue gap ≥ 60°
  1721→  1721  
  1722→  1722  1. **Anti-overlap**: If >6 x-axis labels, rotate 45° (`plt.xticks(rotation=45, ha='right')`)
  1723→  1723  2. **Anti-stretch**: Always set figure size explicitly (`fig, ax = plt.subplots(figsize=(10, 6))`)
  1724→  1724  3. **Aspect ratio (CRITICAL)**: When embedding in docx, MUST read actual image dimensions and calculate height proportionally. NEVER hardcode both width and height — pie charts become ellipses, radar charts become diamonds.
  1725→  1725     ```js
  1726→  1726     const sizeOf = require("image-size");
  1727→  1727     const dims = sizeOf(chartBuffer);
  1728→  1728     const displayWidth = 500;
  1729→  1729     const displayHeight = Math.round(displayWidth * (dims.height / dims.width));
  1730→  1730     // transformation: { width: displayWidth, height: displayHeight }
  1731→  1731     ```
  1732→  1732  4. **DPI**: Save at 200+ DPI (`plt.savefig("chart.png", dpi=200, bbox_inches="tight")`)
  1733→  1733  5. **Colors**: Use palette accent color for primary data series
  1734→  1734  6. **Legend**: Place outside plot area if >4 series
  1735→  1735  7. **Square charts**: Pie and radar charts MUST use `figsize=(8, 8)` (equal width/height) to preserve circular/radial shape
  1736→  1736  7. **Grid**: Light gray grid (`ax.grid(True, alpha=0.3)`)

  1751→  1751  - **Line spacing**: Same 1.3x

  1755→  1755  - Use monospace or tabular figures if available
