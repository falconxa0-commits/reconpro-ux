     7→## Phase 1 — v7.0: Async Core & Evasion Engine
     8→
     9→### 1.1 Asynchronous Engine Core
    10→**Problem**: All HTTP goes through `urllib.request` (sync). Max throughput: ~100 req/s per thread. Blitz uses ThreadPoolExecutor (4-8 workers default). Can't scale to thousands of concurrent connections.
    11→
    12→**Architecture**:
    13→```
    14→reconpro/
    15→  async_http.py      (NEW — ~400 lines)
    16→    - AsyncSession: wraps aiohttp ClientSession with connection pooling
    17→    - AdaptiveLimiter: token-bucket that auto-tunes based on 429/timeout rates
    18→    - RawSocket: optional raw SYN scanner using scapy (if installed)
    19→    - Backward compat: sync wrapper so existing modules keep working
    20→
    21→  engine.py          (NEW — ~300 lines) 
    22→    - ScanEngine: replaces scan() in scanner.py
    23→    - Manages async task queue, module execution, result aggregation
    24→    - Runs modules concurrently (not sequentially like today)
    25→    - Emits events: on_finding, on_module_start, on_module_complete
    26→    - Progress callbacks for TUI integration
    27→```
    28→
    29→**Migration Strategy**:
    30→- Add `aiohttp>=3.9` as optional dep (`pip install reconpro[async]`)
    31→- Keep urllib as fallback for zero-dep mode
    32→- Rewrite scanner.py to use engine.py internally
    33→- Each module gets `async_run()` alongside existing `run()`
    34→- Modules that don't have async versions get wrapped in `asyncio.to_thread()`
    35→
    36→**Target**: 10,000+ concurrent connections, 50x throughput improvement
    37→
    38→### 1.2 Low-Level Raw Packet Assembly
    39→**Problem**: Port scanning uses urllib-based HTTP probes on top-20 ports. Can't do real SYN scans, UDP probes, or custom flag manipulation.
    40→
    41→**Architecture**:
    42→```
    43→reconpro/
    44→  raw_sockets.py     (NEW — ~350 lines)
    45→    - SynScanner: raw TCP SYN scan (requires root/scapy)
    46→    - UdpProber: custom UDP payload sender
    47→    - ArpSpy: ARP table discovery on local network
    48→    - TtlAnalyzer: TTL-based OS fingerprinting
    49→    - Graceful fallback: if no scapy/root, falls back to connect() scan
    50→
    51→  modules/
    52→    portscan.py     (NEW — ~250 lines, replaces port checks in recon.py/host.py)
    53→    - Full 65,535-port scan mode
    54→    - Service version detection via banner grabbing
    55→    - OS fingerprinting via TTL/probe responses
    56→```
    57→
    58→**Dependencies**: `scapy>=2.5` (optional, `[raw]` extra)
    59→
    60→### 1.3 Adaptive Rate-Limiting Engine
    61→**Problem**: Current `RateLimiter` in http.py is a simple token bucket (fixed rate). Doesn't adapt to target behavior.
    62→
    63→**Architecture**:
    64→```
    65→reconpro/async_http.py  (extends existing)
    66→  AdaptiveLimiter:
    67→    - Tracks: response_time_ema, error_rate_ema, timeout_rate
    68→    - On 429/503: multiply rate by 0.5, add jitter
    69→    - On timeout: reduce concurrent connections by 25%
    70→    - On fast responses (<200ms): increase rate by 10% (up to max)
    71→    - Per-target rate tracking (separate limiter per domain)
    72→    - Config: min_rps, max_rps, backoff_factor, recovery_time
    73→```
    74→
    75→### 1.4 Behavioral Footprint Shifting
    76→**Problem**: Every request has identical structure — same headers, same timing, same TLS fingerprint. Easy to detect and block.
    77→
    78→**Architecture**:
    79→```
    80→reconpro/
    81→  evasion.py         (NEW — ~300 lines)
    82→    - HeaderRotator: cycles through 50+ real browser UA strings
    83→    - TlsFingerprint: randomizes TLS cipher suites, extensions order
    84→    - TimingJitter: adds gaussian-distributed delays (mean=0, stddev=configurable)
    85→    - PathCanonicalization: alternates between /path, /./path, /../ normalization
    86→    - CookieJar: maintains per-target cookie state across requests
    87→    - RefererChain: simulates realistic navigation patterns
    88→    - ProfileManager: loads evasion profiles from ~/.reconpro/profiles/
    89→```
    90→
    91→### 1.5 Decentralized Proxy Routing
    92→**Problem**: All scans originate from one IP. Large-scale audits need distributed origins.
    93→
    94→**Architecture**:
    95→```
    96→reconpro/
    97→  proxy.py           (NEW — ~250 lines)
    98→    - ProxyPool: manages list of proxies (HTTP/SOCKS5/rotate)
    99→    - Sources: file input, ProxyList API, TOR circuit rotation
   100→    - Health checking: async probe of all proxies, auto-removal of dead ones
   101→    - RotatingStrategy: round-robin, random, least-connections, geo-distributed
   102→    - Integration: AsyncSession accepts proxy_pool parameter
   103→
   104→  modules/
   105→    distributed.py   (NEW — ~200 lines)
   106→    - Split target list across proxy origins
   107→    - Aggregate results with origin metadata
   108→    - Detect IP-based blocking by comparing results across proxies
   109→```

   132→  swarm.py           (MODIFY — connect to UnifiedMemoryStore)

   136→
   137→### 2.2 Multi-Vector Attack-Path Chaining
   138→**Problem**: Each finding is independent. A low-severity info leak + missing header + open redirect could chain into account takeover, but ReconPro doesn't see the connection.
   139→
   140→**Architecture**:
   141→```
   142→reconpro/
   143→  chain_engine.py    (NEW — ~500 lines)
   144→    - AttackPathFinder: takes KnowledgeGraph, finds compound attack paths
   145→    - ChainRules: 50+ predefined chain patterns:
   146→      - Info leak + open redirect → credential phishing URL
   147→      - Missing CSP + XSS payload → stored XSS
   148→      - CORS wildcard + authenticated API → cross-origin data theft
   149→      - Cloud metadata SSRF + IAM misconfig → full cloud takeover
   150→      - JWT no-verify + weak signing key → token forgery
   151→    - LLM-assisted chain discovery: send graph to LLM, ask "what compound paths exist?"
   152→    - Scoring: chain severity = max(child severities) * 1.5 + path_length_bonus
   153→    - Output: ChainReport with step-by-step attack narrative
   154→
   155→  modules/
   156→    chain_analysis.py (NEW — wraps chain_engine for scan integration)
   157→```
   158→
   159→### 2.3 Inter-Language AST Tracking (Taint Analysis)
   160→**Problem**: Current ast_analyzer.py checks single files in isolation. Can't track `user_input = request.get("x")` flowing through 3 Python files into a SQL query.
   161→
   162→**Architecture**:
   163→```
   164→reconpro/modules/
   165→  ast_analyzer.py   (MAJOR REWRITE — ~1200 lines)
   166→    - TaintTracker: inter-procedural, inter-file taint analysis
   167→      - Phase 1: Build call graph (who calls whom)
   168→      - Phase 2: Identify sources (user input, env vars, file reads, DB)
   169→      - Phase 3: Propagate taint through assignments, function calls, returns
   170→      - Phase 4: Check if tainted data reaches sinks (SQL, eval, exec, os.system)
   171→    - Supported languages:
   172→      - Python: real AST walking (already exists, upgrade to taint)
   173→      - JavaScript/TypeScript: tree-sitter based (optional dep)
   174→      - Go: tree-sitter based (optional dep)
   175→    - Cross-language: if Python calls subprocess(["node", "x.js", user_input]) → track across boundary
   176→    - Output: TaintReport with full data flow path: source → propagation → sink
   177→
   178→  deps: tree-sitter>=0.21 (optional, `[ast-full]` extra)
   179→```
   180→

   198→  data/

   307→### 3.4 Granular Secret Entropy Scoring
   308→**Problem**: dev.py uses 13 regex patterns. High false-positive rate — matches random strings that aren't secrets.
   309→
   310→**Architecture**:
   311→```
   312→reconpro/
   313→  entropy.py         (NEW — ~200 lines)
   314→    - ShannonEntropy: calculates entropy of a string
   315→    - SecretClassifier: ML-inspired scoring:
   316→      - High entropy (>4.0) + known prefix (AKIA, ghp_, gsk_, xoxb-, etc.) → CRITICAL
   317→      - High entropy + assignment context (API_KEY=, password=, token=) → HIGH
   318→      - High entropy + no context → MEDIUM (likely false positive)
   319→      - Low entropy + known pattern (password123) → HIGH
   320→      - Format validation: AWS keys (20+40 chars, specific regex), GitHub tokens (36 hex), JWT structure
   321→    - ContextAnalysis: checks surrounding code for:
   322→      - Variable names (contains: key, secret, token, password, cred, auth)
   323→      - File names (.env, credentials, config, secrets)
   324→      - Adjacent comments (TODO: remove, FIXME, temporary)
   325→    - Integration: replaces _check_hardcoded_secrets() in dev.py and _scan_for_tokens() in nhi.py
   326→```

   484→## Phase 5 — v9.0: Next-Gen Features (My Additions)
   485→
   486→### 5.1 Live Traffic Interception & Replay
   487→**Why**: Most recon tools only see the current snapshot. Real attacks exploit timing — intercepting live traffic reveals runtime secrets, session tokens, and API patterns that static analysis misses.
   488→
   489→**Architecture**:
   490→```
   491→reconpro/
   492→  mitm.py            (NEW — ~500 lines)
   493→    - ProxyInterceptor: MITM proxy that logs all HTTP/HTTPS traffic
   494→    - Based on mitmproxy library (optional dep)
   495→    - Auto-discovers: API endpoints, auth tokens, session cookies, hidden params
   496→    - TrafficReplay: replay requests with modifications (auth removal, param tampering)
   497→    - SessionHijackTest: replay session tokens from different origins
   498→    - Integration: `reconpro intercept --port 8080` starts proxy, then `reconpro analyze-traffic`
   499→```
   500→
   501→### 5.2 Passive DNS & Historical Intel
   502→**Why**: Current subdomain discovery is active (CT logs + DNS brute). Passive DNS databases contain years of historical records that reveal deprecated subdomains still pointing to old infrastructure.
   503→
   504→**Architecture**:
   505→```
   506→reconpro/
   507→  passive_intel.py   (NEW — ~300 lines)
   508→    - PassiveDNS: queries VirusTotal, SecurityTrails, Shodan APIs for historical DNS
   509→    - WaybackMachine: fetches archived versions of target pages
   510→    - CertificateTransparency: enhanced CT log search with historical cert analysis
   511→    - DeprecationDetector: finds subdomains with stale DNS (pointing to decommissioned IPs)
   512→    - TechHistory: tracks technology changes over time (WordPress → Laravel migration = exposed wp-admin)

   561→### 5.5 Smart Recon Profiler (Target Fingerprinting)
   562→**Why**: Currently every target gets the same scan. A WordPress site needs different tests than a React SPA or a Java Spring API.
   563→
   564→**Architecture**:
   565→```
   566→reconpro/
   567→  profiler.py        (NEW — ~350 lines)
   568→    - TargetProfiler: runs a 30-second rapid assessment to classify the target
   569→    - Classification:
   570→      - Technology stack (language, framework, server, CDN, WAF)
   571→      - Application type (SPA, SSR, API-only, static site, microservices)
   572→      - Authentication model (none, session, JWT, OAuth, API key, mTLS)
   573→      - Infrastructure (cloud provider, region, load balancer, caching)
   574→      - Security posture estimate (based on headers, CSP, HSTS, etc.)
   575→    - AutoPlan: given the profile, selects optimal module combination:
   576→      - WordPress → recon + auth + vibesec + bot + nhi (skip gorgon SQLi)
   577→      - React SPA → recon + chain + api_discovery + vibesec
   578→      - Java API → recon + auth + chain + gorgon + nhi + cve_enrichment
   579→    - Integration: `scan()` calls profiler first, then runs selected modules
   580→    - Saves profiles: ~/.reconpro/profiles/{target}.json for faster re-scans
   581→```

   588→reconpro/

   602→### 5.7 Zero-Trust Network Mapper
   603→**Why**: host.py checks the local machine. Doesn't map the network topology or find lateral movement paths.
   604→
   605→**Architecture**:
   606→```
   607→reconpro/
   608→  netmap.py          (NEW — ~400 lines)
   609→    - NetworkDiscovery: ARP scan, ping sweep, mDNS discovery
   610→    - ServiceFingerprinting: probe open ports, identify services and versions
   611→    - TrustRelationshipMapper:
   612→      - SSH key trust chains (who can SSH into whom)
   613→      - Docker network topology (container-to-container communication)
   614→      - K8s network policies (actual vs declared)
   615→      - Active Directory trust relationships (if on Windows domain)
   616→    - LateralPathFinder: given a compromised host, find all reachable hosts
   617→    - SegmentationChecker: verify network segmentation between zones
   618→    - Visual output: network graph with trust relationships
   619→    - Integration: `reconpro netmap --subnet 192.168.1.0/24`
   620→```

   622→### 5.8 Scheduled Competitive Benchmarking
   623→**Why**: Security posture degrades over time. Teams need continuous scoring against their own history and industry peers.
   624→
   625→**Architecture**:
   626→```
   627→reconpro/
   628→  benchmark.py       (NEW — ~300 lines)
   629→    - ScoreTracker: time-series of security scores per target
   630→    - BenchmarkRunner: scheduled scans that track score trends
   631→    - Comparisons:
   632→      - Self: score today vs last week vs last month
   633→      - Team: score of project A vs project B vs team average
   634→      - Industry: anonymous aggregate scores from opt-in telemetry
   635→    - Alerts: score drops below threshold → notification
   636→    - Leaderboard: `reconpro benchmark --team --period 30d`
   637→    - Integration with scheduler.py for automated periodic benchmarking
   638→```
