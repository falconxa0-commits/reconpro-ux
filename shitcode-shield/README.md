Free for open source. Paid for private repos.

## Quick Start

Add this to your repo's `.github/workflows/vibesec.yml`:

```yaml
name: ShitCode Shield
on:
  pull_request:
    types: [opened, synchronize, reopened]

jobs:
  shitcode-shield:
    runs-on: ubuntu-latest
    steps:
      - uses: reconpro/shitcode-shield@v0.1.0
        with:
          github-token: ${{ secrets.GITHUB_TOKEN }}
```

That's it. Every PR will now get a ShitCode Shield report.

## What It Does

ShitCode Shield runs two analyses on every PR:

### 1. AI Code Detection

Identifies AI-generated code using heuristics:

- **Comment markers:** Detects `// Generated by AI`, `// Copilot`, `// Claude`, etc.
- **Statistical signals:** High comment-to-code ratio (>40%), perfect JSDoc on every function, alphabetized imports
- **Code smell signals:** No TODO/FIXME/HACK comments, perfectly consistent formatting, 100+ lines added at once

### 2. Security Vulnerability Scan

Scans the diff for security issues without making any network requests:

- **Exposed secrets:** Stripe keys, GitHub tokens, AWS keys, GCP keys, JWTs, Supabase keys, Firebase keys, connection strings
- **Hardcoded credentials:** `admin/admin`, `root/password`, `test/test`
- **Insecure patterns:** `eval()`, `innerHTML`, `dangerouslySetInnerHTML`, wildcard CORS, disabled TLS
- **SQL injection:** String concatenation in SQL queries
- **Missing auth:** New API routes without authentication middleware
- **Debug code:** `console.log`, `debugger`, `print()` in production files

## Configuration

| Input | Required | Default | Description |
|-------|----------|---------|-------------|
| `github-token` | ✅ | — | GitHub token for posting comments. Use `${{ secrets.GITHUB_TOKEN }}` |
| `scan-deployed-url` | ❌ | — | Also scan a deployed URL with the VibeSec live scanner |
| `fail-on-critical` | ❌ | `true` | Exit with error code 1 if critical findings are found |
| `comment-style` | ❌ | `branded` | Comment style: `branded` or `minimal` |

## .vibesec-ignore

Create a `.vibesec-ignore` file in your repo root to skip files. One glob pattern per line:

```
# Skip generated files
*.generated.*
src/generated/*

# Skip test fixtures
*.test.ts
__tests__/*

# Skip migration files
prisma/migrations/*
```

## Outputs

The action sets the following outputs for use in subsequent steps:

| Output | Type | Description |
|--------|------|-------------|
| `score` | number | VibeSec score (0-100) |
| `grade` | string | Letter grade (A+ through F) |
| `findings-count` | number | Total number of security findings |
| `ai-files-count` | number | Number of files flagged as AI-generated |
| `critical-count` | number | Number of critical findings |
| `high-count` | number | Number of high findings |

## Full Example Workflow

```yaml
name: ShitCode Shield
on:
  pull_request:
    types: [opened, synchronize, reopened]

permissions:
  pull-requests: write
  contents: read

jobs:
  shitcode-shield:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: reconpro/shitcode-shield@v0.1.0
        id: shield
        with:
          github-token: ${{ secrets.GITHUB_TOKEN }}
          scan-deployed-url: 'https://preview-${{ github.event.pull_request.number }}.example.com'
          fail-on-critical: 'true'
          comment-style: 'branded'

      # Use outputs in downstream steps
      - name: Check grade
        if: steps.shield.outputs.grade == 'F'
        run: |
          echo "PR got an F grade. Score: ${{ steps.shield.outputs.score }}"
```

## How It Works

```
PR opened
    │
    ▼
Fetch PR diff via GitHub API
    │
    ├─► AI Code Detection (heuristic analysis)
    │     └─► Detects AI markers, comment ratios, JSDoc patterns
    │
    ├─► Diff Security Scan (pattern matching, no HTTP)
    │     └─► Secrets, insecure patterns, debug code, missing auth
    │
    ├─► [Optional] Live URL Scan (VibeSec Python scanner)
    │     └─► CORS, security headers, exposed endpoints
    │
    ▼
Merge results → Compute VibeSec Grade (A+ to F)
    │
    ▼
Post branded comment on PR
    │
    ▼
Fail check if critical findings (optional)
```
